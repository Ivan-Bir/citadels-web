# Citadels Web: устройство проекта

## Основные источники

Для терминов и различий «ход/раунд», «номинал/плата», «размер города/число карт», «копирование/передача» используй [GLOSSARY.md](GLOSSARY.md). Настройка хоста, локальный запуск и параметры партии описаны в [README.md](README.md).

| Файл | Назначение |
|---|---|
| `module.js` | Подключение игры к хосту, `GameState`, события, фазы, способности, таймеры и снимки |
| `utils.js` | Создание и перемешивание колоды, раздача, добор и сброс |
| `public/setup.js` | Общий каталог, нормализация сетапа, доменные ограничения, стоимость, доход и очки |
| `district-scoring.js` | CommonJS-реэкспорт функций подсчёта из `public/setup.js`, используемый сервером |
| `public/app.jsx` | React-компоненты игры, редактор настроек, просмотр сетапа, клиентские события |
| `public/app.html`, `public/style.css` | Загрузка клиентских ресурсов и оформление |
| `test/`, `test-support/` | Тесты Node.js и заглушка окружения движка |

## Архитектура и границы данных

Игра — подключаемый пакет CommonJS. Хост `ws-server-engine` предоставляет HTTP/WebSocket, идентификацию пользователей, комнаты, сохранение снимков и общие клиентские библиотеки. Клиентский JSX компилируется Babel в браузере; отдельного этапа сборки нет.

```text
ws-server-engine
  └─ require("citadels")(wsServer, "/bg/citadels")
       └─ module.js / GameState
            ├─ utils.js → public/setup.js
            ├─ room → событие state → Game в public/app.jsx
            └─ state.players[slot] → player-state владельцу места

public/app.html → public/setup.js → public/app.jsx + public/style.css
```

`init(wsServer, path)` регистрирует страницу игры и менеджер комнат; ресурсы из `public/` доступны под `/citadels`. Хост дополняет HTML библиотеками и данными подключения, поэтому страница запускается через `/bg/citadels`.

- `room` — публичное состояние: места, фаза, активные игрок/персонаж, золото, количества карт руки, города, раскрытые роли, счёт и таймер. `update()` отправляет его игрокам и наблюдателям.
- `state` — закрытое серверное состояние: руки, порядок колоды и сброс, назначения персонажей, скрытые цели и служебные поля способностей. `sendState(user)` отправляет персональный `player-state`; наблюдатель получает пустой объект.
- `gameSetup` хранится в `room` для снимков, но исключён из обычного `state`. Он передаётся отдельно событием `game-setup` при входе и старте партии.

Руки, скрытые роли, порядок колоды и тайные цели остаются в закрытом состоянии. Например, публичный эффект Дома заговорщиков показывает источник эффекта, а цель передаётся только владельцу.

## Событийная модель

Клиент `Game` вызывает `CommonRoom.roomInit`, подписывается на события и отправляет `init`. Вход, подключение и общие операции комнаты обслуживает движок.

Игровой `userEvent(user, event, data)` направляет запрос в `userEventHandlers` либо определяет место пользователя и вызывает `slotEventHandlers`. Основные запросы: `start-game`, `take-character`, `discard-character`, `take-resources`, `take-card`, `build`, `end-turn`; способности имеют отдельные события.

Ответы сервера: `state`, `player-state`, `game-setup`, `setup-error`, `message`. Разовые визуальные и звуковые сигналы могут передаваться вместе с публичным `state`; например, `mirrorBuild` запускает превращение Чертога и не сохраняется в снимке.

Проверки фазы, места, роли, текущего действия, индексов, ресурсов и ограничений находятся в серверных обработчиках. Для активных способностей кварталов используются `districtActionAllowed`, `districtSource`, `useDistrict`. Доступность кнопки на клиенте не заменяет серверную проверку.

## Раунд, персонажи и ход

| `room.phase` | Состояние |
|---:|---|
| `0` | Лобби или завершённая партия |
| `1` | Выбор персонажей |
| `1.5` | Очередь обменов через Театры после выбора |
| `2` | Основной ход персонажа |
| `3` | Временный выбор или просмотр карт |

Основной маршрут в `module.js`:

```text
startGame → newRound → nextChoose / nextChoose2
  → beginTheaters / nextTheater → nextCharacter → startTurn
  → finishTurn → endRound → newRound или endGame
```

Персонаж имеет ID вида `rank_variant`, например `4_1`. Выбранные роли находятся в `state.players[slot].character`, соответствие роли игроку — в `state.characterRoles`. Выбор остаётся скрытым до вызова персонажа. `nextCharacter()` идёт по порядку `room.characterInGame`, пропуская невыбранных и убитых персонажей.

Каждый реально начавшийся ход персонажа увеличивает `room.turnId`. Несколько персонажей одного игрока дают отдельные ходы. Передача управления Ведьме внутри уже начавшегося хода нового `turnId` не создаёт. Во время ответных действий `currentPlayer` также может указывать на Магистрата или Шантажиста, а не на первоначального владельца активной роли.

Основной ход включает получение ресурсов, строительство и способности. Обычный ресурс — два золотых либо просмотр двух карт с сохранением одной; персонажи и кварталы изменяют эти значения. Базовый лимит строительства — один квартал, с явными исключениями способностей. Текущая допустимость действия зависит и от фазы, и от `state.players[slot].action`.

Достигнутый размер города записывает `room.ender`; партия заканчивается в конце раунда. Автоматический порог — восемь для троих игроков, семь для остальных составов. В начатой партии действует сохранённый `state.maxDistricts`. Итог учитывает номиналы, эффекты и настроенные бонусы; при равенстве сравниваются сумма напечатанной стоимости и золото, возможна общая победа.

## Жизненный цикл квартала

В каталоге `districts[id].type` — числовой цвет; в экземпляре `{type, cost, kind}` поле `type` — строковый ID, `kind` — цвет. Категории: `4` дворянская, `5` церковная, `6` торговая, `8` воинская, `9` особая, `0` бесцветная. `getDistrictType` сохраняет значение `0`.

- `createDeck` создаёт физические объекты карт. Раздача и добор перемещают их из колоды в руку или временный `player.choose`.
- При выборе ресурса оставленные карты переходят в руку, остальные — в сброс. `choose` также может содержать чужую руку, персонажей или копии для просмотра; назначение определяют `chooseSource` и `action`.
- `discardDistrictCards` потребляет переданный массив через `splice(0)`. При передаче части руки сначала отделяется эта часть, чтобы у карты оставался один владелец.
- `drawDistrictCards` берёт карты с начала колоды. Когда она пуста, перемешивается весь сброс; если обе стопки пусты, возвращается частичный или пустой результат. Счётчики обновляются по фактическому числу карт.
- `build()` проверяет плату, лимит, повторки и запрет строительства, переносит карту из руки в город и назначает `instanceId` вида `district-N`.
- Номинальный `cost` и плата за строительство различаются. Постоянный `buildDiscount`, украшения и другие свойства принадлежат экземпляру. Размер города вычисляет `getCityDistrictCount`: Монумент даёт два, Катакомбы — ноль.
- `actionsUsed` ограничивает способности каждого построенного экземпляра по `turnId`. Обычная новая постройка очищает использование; перенос здания сохраняет его состояние, кроме специальных правил эффекта.
- Захват, обмен и конфискация перемещают существующий объект между городами. `winery` обнуляет `wineAge` при смене владельца и обычной постройке, увеличивает возраст один раз в конце раунда.
- Зеркальный чертог создаёт независимую глубокую копию здания с его состоянием и новыми ID, включая вложенную экспозицию. Театр копировать нельзя.
- Музей хранит карты в `exposition`. Разрушение отправляет здание и экспозицию в сброс; уничтоженная постройка не возвращается прямо в колоду.

## Сетап, сохранение и клиент

`public/setup.js` — UMD-модуль: сервер получает его через `require`, браузер как `CitadelsSetup`. Это общий источник каталога, правил и вычислений. Формат `citadels-setup` версии 1 содержит `districts`, `characters`, `timer`, `starting`, `rules`, необязательные `metadata`.

Нормализация проверяет структуру; `getStartErrors` дополнительно проверяет возможность старта с текущими игроками. Хозяин запускает партию только после всех проверок. Отсутствующая базовая колода означает стандартные количества; явный `{}` — ноль базовых карт. Все выбранные особые включаются в колоду. Начальные ресурсы по умолчанию — четыре карты и два золотых; корона назначается до раздачи и получает предусмотренные уменьшения.

`getSnapshot()` возвращает серверные `{room, state}`, включая скрытые данные. `setSnapshot()` восстанавливает состояния, очереди, счётчики экземпляров, производный счёт и таймеры. Сохранение передаётся движку, а не публичным игровым клиентам.

Таймеры бывают `character`, `main`, `response`. Ответное действие может приостановить основной таймер; `timerId` защищает от устаревших callback. Истечение времени проходит через предусмотренный выбор, отказ или завершение хода, поэтому изменения способностей затрагивают и обычный ответ, и таймаут.

Клиентские компоненты: `Game`, `CreateGamePanel`, `SetupViewer`, `Card`, `DistrictFace`. Черновик сетапа хранится в `sessionStorage` отдельно по пользователю и комнате; редактирование не отправляет серверные события. Общий фон партии — отдельное предпочтение: он не входит в JSON сетапа, применяется при старте и передаётся как публичный `backgroundId`.

Изображения кварталов имеют пути `public/cards/<id>.jpg`, персонажей — `public/characters/<rank_variant>.jpg`. Жетоны в `public/character-tokens/` используются отдельно; увеличение показывает полную карточку. У `Card` обычная и увеличенная поверхности, а `fullCardImage` отображает готовую карту целиком.

## Локальный запуск и проверки

Подготовь соседний хост `meme-police` по [инструкции README](README.md#локальный-запуск-windows-linux-macos): нужны Node.js/npm, Git и доступ к `ws-server-engine`. Зависимость хоста на игру — `citadels: file:../citadels-web`; конфигурация движка и `app.js` приведены там же.

```sh
cd ../meme-police
npm install
npm start
```

Адрес примера: `http://localhost:3000/bg/citadels#local-test`; хеш задаёт комнату. Порт и origin определяются конфигурацией хоста. Для разных игроков нужны отдельные профили браузера. Установка и запуск в WSL выполняются Linux-инструментами; подробности — в README.

В папке игры `npm test` запускает встроенный `node:test` без движка. Тесты колоды проверяют состав и сохранность объектов, а не случайный порядок. Серверные сценарии используют `test-support/game.cjs`; клиентские тесты выполняют реальные методы клиента.

После изменения сервера или `public/setup.js` перезапускается хост; клиентские изменения требуют обновления страницы. Движок кэширует HTML до перезапуска. JSX проверяется браузером или Babel, обычный `node --check` для него не подходит.
